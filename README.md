# inline 訂位快手

可放進 Git 的 Chrome／Edge Manifest V3 擴充功能。輸入 inline 餐廳名稱或官方訂位網址，再填日期區間、時間區間、人數及聯絡資料，工具會尋找可用時段並協助填寫資料。付款、條款同意與最後訂位確認由使用者操作。

## 功能

- 可輸入餐廳名稱或關鍵字，也可貼上完整網址、`inline.app/booking/...`、`/booking/公司ID/分店ID` 或含 `/form` 的訂位網址。
- 可設定最多 14 天的日期區間，以及可接受的時間區間。
- 分開設定大人與小孩人數。
- 姓名、電話與 Email 只儲存在目前瀏覽器的擴充功能空間。
- 訂位資料區有明確的「儲存設定」按鈕，並顯示已儲存時間或尚未儲存的變更；「現在開始找位」與「設定排程」也會同步儲存目前設定。
- GitHub／背景版本之外，更新區會顯示 inline 頁面實際載入的助手版本，避免檔案已下載但舊頁面仍在執行舊程式。
- 進入需要綁定信用卡的頁面時，會先填妥可辨識的訂位人姓名、手機、Email 與用餐目的，並停止自動流程。信用卡、付款與最後確認由使用者在 inline 頁面操作。
- 若先前流程已停止，但目前仍停留在同一次訂位的 `/form` 頁，可在外掛按「補填目前頁面的聯絡資料」；已手動填寫的欄位會保留。
- 更新後如任務已停止，可在同一次訂位的 inline 分頁按「繼續目前訂位頁」；外掛重新接手後會填聯絡資料，遇到條款會自動將規則捲到底，等待使用者在頁面提示明確同意，再繼續至付款前。
- 同一餐廳若意外開出多個表單分頁，會由目前顯示中的表單接手流程；套用插件更新後會把新版頁面助手直接注入所有已開啟的 inline 訂位頁，再由目前任務分頁接手。
- 所有執行方式都會停在付款、條款同意或最後確認前。規則內容會自動捲到底；使用者按下外掛的同意按鈕時，外掛才代按 inline 同意並繼續填資料。
- 找到最後確認按鈕時，頁面會顯示「尚未送出訂位」提示；請使用者自行核對後操作。
- 每次任務只允許插件剛開啟的那一個分頁執行；舊的 inline 訂位頁不會再讀取新餐廳任務。搜尋到多家分店（例如涮乃葉）時會停下讓你選擇，不會擅自套用舊餐廳網址。
- 遇到 CAPTCHA 會暫停；手動通過後會偵測頁面變化並接續。
- CAPTCHA 出現時會在頁面顯示操作提示；插件不會破解或模擬長按，手動完成後會自動接續。
- 會核對 inline 畫面實際顯示的日期與已選時段；若網站忽略預填值，不會把錯誤日期或區間外時段當成預演完成或送出。
- inline 忽略網址中的預填日期時，會依月曆的完整 `data-date` 自動切換月份並選擇精確日期；日期不可訂時會繼續檢查設定區間內的下一天。
- 最終授權／確認不由外掛執行。
- 出現信用卡資料欄位、OTP、付款驗證或 CAPTCHA 時會停止；交由使用者在 inline 頁面處理。
- 會辨識餐廳自訂的桌型／餐區，預設選第一個可用選項。
- 若時段另外提供「預先點餐」，會自動選擇「跳過預先點餐」繼續訂位，不會擅自加購餐點。
- 使用共用的流程階段辨識，不綁定單一餐廳版面；會辨識選位、額外選購、訂位資料、條款、付款與最後確認。
- 「跳過／略過／稍後／不需要」等明確安全的額外選購可自動繼續；取消、返回、付款、授權與送出不會被當成略過按鈕。
- 一般頁面步驟採約 80ms 的快速反應，跨日期或需等待頁面切換時保留約 240ms，兼顧速度與防止重複點擊。
- 可設定常見的「用餐目的」；其他未知必填題會標示並暫停，不會卡死。
- 條款按鈕會依 `aria-checked`／`data-state` 判斷是否已同意；已勾選時不會反覆切換，會直接繼續填入姓名、手機、Email 與用餐目的。未同意時會自動捲動規則視窗，並在按鈕啟用後提供明確的同意操作。
- 隱藏且非必填的條款控制，以及只有說明文字、沒有實際控制項的條款標籤，都會略過，不再阻擋聯絡資料填寫。
- 可立即開始，也可設定未來啟動時間及提前暖機。
- 「現在開始找位」與排程驗證完全分離；排程時間即使空白或已過期，也不會擋住立即開始。
- GitHub 版本區固定顯示「檢查更新」按鈕。開啟插件時不會連線查詢 GitHub；只有使用者親自按下按鈕才會檢查並下載新版。
- 新版檔案覆蓋到原資料夾後，插件只在本機比對畫面與背景版本。若兩者不同，會顯示「套用插件更新」；仍要由使用者親自按下才會重新載入插件，不會自動套用。

## 安裝

1. Chrome 開啟 `chrome://extensions`；Edge 開啟 `edge://extensions`。
2. 開啟「開發人員模式」。
3. 按「載入未封裝項目」。
4. 選擇本資料夾 `inline-reservation-helper`。
5. 把插件釘選到瀏覽器工具列。

## 使用

1. 打開插件，輸入餐廳名稱或 inline 官方訂位網址。
2. 填入可接受的開始／結束日期、最早／最晚時間及人數。
3. 填入訂位姓名、手機與 Email。
4. 選擇用餐目的偏好。
5. 按「現在開始找位」，或在進階選項填入啟動時間後按「設定排程」。
6. 如果以名稱搜尋且出現多家分店，手動選擇正確分店一次，插件就會接續。
7. CAPTCHA 與 OTP 由你手動處理；到付款頁時請在 inline 頁面自行填寫信用卡、確認付款與最後訂位。無法辨識或存取的金流欄位須手動填寫。

## 已實測的 inline 流程

- inline 訂位頁 8.32.2：大人／小孩、日期、一般時段、額滿時段、訂位摘要與資料表單。
- 免訂金流程：姓名、性別、國碼、電話、Email、用餐目的、備註、行銷勾選與「確認訂位」。
- 訂金／預授權流程：桌型或餐區、帶金額的時段、「授權信用卡及確認訂位」與 CAPTCHA 前置驗證。
- 規則／注意事項、信用卡授權、付款及最後確認都需要使用者自行操作。外掛不會因一般說明文字宣稱訂位成功。
- inline Dining 1.55.0：名稱不再拼進網址，避免新版頁面解析出現 `Invalid URL`。插件會先透過 inline 官方搜尋服務取得並驗證訂位網址；同名結果不明確時，才開啟 Dining 頁面讓使用者確認分店。

流程採逐頁狀態判斷，不以整頁出現「訂金」或「信用卡」文字就誤判；只有出現真正的卡片欄位、OTP、付款驗證控制項或 CAPTCHA 才會暫停。

## 手動更新機制

本工具不會在背景自行安裝新版。

- 下載新版並覆蓋資料夾後，仍由使用者自行到擴充功能管理頁按「重新載入」；插件不會自行重新啟動。
- 若要從 GitHub 偵測新版，先建立 GitHub repository，並在 `update-config.js` 填入 `帳號/repository`。
- 每次發布新版時建立 GitHub Release，標籤使用 `v0.3.8` 這類版本格式，並附上 `inline-reservation-helper.zip`。插件每次顯示時都會重設為「尚未手動檢查」，並忽略開啟瞬間或程式觸發的點擊；只有使用者親自按下「檢查更新」後才讀取最新 Release。發現新版時按鈕會改成「下載 vX.Y.Z」，但不會自行檢查、下載、安裝或重新載入。
- 按「更新」會開啟新版 Release 頁。下載後解壓覆蓋原資料夾，再到擴充功能頁按「重新載入」。瀏覽器不允許未封裝擴充功能自行覆蓋安裝檔案。

## 使用界線

- 不繞過 CAPTCHA、簡訊驗證、付款驗證或存取限制。
- 不呼叫未公開 API，不高頻輪詢，不同時大量建立訂位。
- 不用於代訂、轉售、囤位或造成服務負載。
- 餐廳與 inline 當日顯示的規則永遠優先。

使用前請自行閱讀 [inline 使用條款](https://restaurant.inline.app/tos) 與餐廳訂位規則。

## 已知限制

- 不同餐廳的欄位與流程可能不同；找不到安全且明確的按鈕時會停止並提示手動處理。
- 名稱搜尋遇到同名餐廳或多家分店時，需要手動選擇一次。
- 餐廳可自由新增必填題；工具不會替你猜飲食限制、活動方案等有實質含義的答案，遇到未知問題會停下。
- 電腦休眠時無法準時執行排程。
- 預填與自動點擊不保證有位，結果仍取決於餐廳當下庫存。
- GitHub 版本檢查只支援可讀取 Release 的 repository；尚未設定更新來源時會顯示「Git 開發版」。
